# Card 2 polar terrain implementation plan

> Execute inline with executing-plans; user approved card 2 scope and immediate execution.

Goal: reproducible partial downloads of NASA PGDA south-polar DEM windows.
Architecture: seekable HTTP Range reader with persistent validated blocks; tifffile
decodes only intersecting tiles/strips; pyproj supplies lunar stereographic coordinates.
Spec: docs/1단계_분배.md (card 2), AGENTS.md, docs/data_contract.md.

Constraints: own branch; no web/index.html edits; raw data ignored; English code;
append sources and SI log; no all-core execution. New clone isolates this work.

1. Write tests for HTTP range rejection, cached restart, projection axis signs,
   pixel registration and window decoding; observe missing-module failure.
2. Implement pipeline/fetch_polar.py and dependency list; pass tests.
3. Inspect real TIFF metadata; run one site then all three placeholder sites at
   six resolutions, saving metadata, byte counts and resumable blocks.
4. Independently compare cached heights and georeferencing; report actual errors,
   never force differences to meet a claimed tolerance. Document commands and limits.
5. Review, verify, append SI log, commit and open PR without merging.

Review focus: servers ignoring Range; interrupted/stale cache; out-of-coverage sites;
pixel-center offsets; nodata and resolution-dependent terrain differences.

Rulings: 20 m radius defaults to 25 km (card leaves it unspecified). Placeholder
coordinates are explicitly synthetic test locations, never authoritative landing sites.
Projected square windows enclose the requested radius. Lunar curvature belongs to
phase-2 horizon computation, not elevation downloads.

## Resolution follow-up

The 9 m pointwise discrepancy is explained by spatial support: fresh source tile bytes match the cache, GDAL reproduces the interpolation, and aligned averaging reproduces the coarse product. Across 1,728 cells, 60/80-to-240 m residuals are at float32 rounding scale; all tested products agree within 2.023 m after area matching. See docs/polar-resolution-diagnosis.md. No production downloader or DEM values changed. Draft status now awaits team agreement on resolution-matched acceptance, not an unresolved suspected code defect.
